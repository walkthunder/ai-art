### ✅ 已修复的问题

#### ~~问题1：payment_orders表的外键约束不合理~~ ✅ 已修复

**原问题：**
```sql
-- 旧设计
generation_id VARCHAR(36) NOT NULL  -- ❌ 充值订单无法创建
CONSTRAINT payment_orders_ibfk_2 
FOREIGN KEY (generation_id) REFERENCES generation_history(id) 
ON DELETE CASCADE
```

**修复方案（016_fix_payment_orders_generation_id.sql）：**
```sql
-- 1. 修改 generation_id 为 NULLABLE
ALTER TABLE payment_orders 
MODIFY COLUMN generation_id VARCHAR(36) NULL 
COMMENT '生成记录ID（充值订单可为空）';

-- 2. 删除旧外键约束
ALTER TABLE payment_orders 
DROP FOREIGN KEY IF EXISTS payment_orders_ibfk_2;

-- 3. 重新添加外键约束（允许NULL）
ALTER TABLE payment_orders 
ADD CONSTRAINT payment_orders_ibfk_2 
FOREIGN KEY (generation_id) REFERENCES generation_history(id) 
ON DELETE SET NULL;

-- 4. 新增订单类型字段
ALTER TABLE payment_orders 
ADD COLUMN order_type ENUM('generation', 'recharge') NOT NULL DEFAULT 'generation' 
COMMENT '订单类型: generation-生成订单, recharge-充值订单';

-- 5. 添加索引
ALTER TABLE payment_orders 
ADD INDEX idx_order_type (order_type);
```

**修复效果：**
- ✅ 充值订单可以创建（generation_id = NULL）
- ✅ 生成订单仍然关联 generation_history
- ✅ 订单类型明确区分
- ✅ 外键约束保持完整性

#### ~~问题2：任务状态未持久化~~ ✅ 已修复

**原问题：**
- 任务状态只存储在内存和文件中
- 服务重启后任务状态丢失
- 无法跨实例共享任务状态
- 扣减的次数无法恢复

**修复方案（017_create_tasks_table.sql）：**
```sql
CREATE TABLE IF NOT EXISTS tasks (
  id VARCHAR(36) PRIMARY KEY COMMENT '任务ID（UUID）',
  user_id VARCHAR(36) NOT NULL COMMENT '用户ID',
  mode VARCHAR(20) NOT NULL COMMENT '模式: puzzle-时空拼图, transform-富贵变身',
  status ENUM('pending', 'processing', 'completed', 'failed', 'timeout', 'cancelled') 
    NOT NULL DEFAULT 'pending' COMMENT '任务状态',
  progress INT NOT NULL DEFAULT 0 COMMENT '进度百分比 0-100',
  message TEXT COMMENT '状态消息',
  
  -- 任务参数和结果（JSON格式）
  params JSON NOT NULL COMMENT '任务参数',
  result JSON DEFAULT NULL COMMENT '任务结果',
  error TEXT DEFAULT NULL COMMENT '错误信息',
  
  -- 重试相关
  retry_count INT NOT NULL DEFAULT 0 COMMENT '重试次数',
  max_retries INT NOT NULL DEFAULT 2 COMMENT '最大重试次数',
  
  -- 时间戳
  created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  started_at TIMESTAMP NULL DEFAULT NULL,
  completed_at TIMESTAMP NULL DEFAULT NULL,
  
  -- 索引
  INDEX idx_user_id (user_id),
  INDEX idx_mode (mode),
  INDEX idx_status (status),
  INDEX idx_created_at (created_at),
  INDEX idx_user_status (user_id, status),
  
  -- 外键
  CONSTRAINT tasks_ibfk_1 FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;
```

**代码更新（taskQueueService.js）：**
```javascript
// 1. 持久化策略：数据库优先 + 文件备份
async function persistTask(task) {
  // 优先写入数据库
  await persistTaskToDatabase(task);
  // 文件作为备份
  await persistTaskToFile(task);
}

// 2. 查询策略：内存 → 数据库 → 文件
async function getTask(taskId) {
  // 1. 从内存获取
  let task = taskQueue.get(taskId);
  if (task) return task;
  
  // 2. 从数据库加载
  task = await loadTaskFromDatabase(taskId);
  if (task) return task;
  
  // 3. 从文件加载（降级）
  task = await loadTask(taskId);
  return task;
}

// 3. 删除策略：同时删除数据库和文件
async function deleteTask(taskId) {
  taskQueue.delete(taskId);
  await deleteFromDatabase(taskId);
  await deleteFromFile(taskId);
}
```

**修复效果：**
- ✅ 任务状态持久化到数据库
- ✅ 服务重启后可以恢复任务
- ✅ 支持跨实例查询任务状态
- ✅ 文件存储作为备份降级方案
- ✅ 超时任务可以自动恢复次数

### 流程2：用户充值流程（已修复）⭐

#### 支付架构说明

项目采用**云函数 + 后端服务器**的混合架构，**共享同一个数据库**：

- **云函数（wxpayFunctions）**：处理微信支付下单和接收微信回调
- **后端服务器（backend）**：管理订单状态、用户权益、余额充值
- **共享数据库**：通过 CloudBase RDB 或直连访问同一个 MySQL 数据库

#### 当前充值方式

**只有小程序充值**：用户在小程序内购买套餐（basic/premium）

#### 完整支付流程

```
用户点击支付
    ↓
小程序调用 cloudbase-payment.js
    ↓
调用云函数 wxpayFunctions (type: wxpay_order)
    ↓
云函数创建订单并存储到数据库
    ↓
调用微信支付 API 获取支付凭证
    ↓
返回支付凭证给小程序
    ↓
小程序调用 wx.requestPayment()
    ↓
用户完成支付
    ↓
微信服务器回调云函数 HTTP 触发器
    ↓
云函数 wxpay_order_callback 处理回调
    ├─ 验证微信签名（可选）
    ├─ 更新数据库订单状态
    └─ 调用 /api/payment/internal/notify
        ↓
        后端处理业务逻辑
        ├─ 更新订单状态（幂等性检查）
        ├─ 充值用户余额
        └─ 更新用户权益
```

#### 支付失败场景处理

**场景 1：用户取消支付**
- 订单状态保持 `pending`
- 不触发任何回调
- 用户可以重新发起支付
- 不会扣除余额

**场景 2：支付超时**
- 订单状态保持 `pending`
- 微信不会发送回调
- 可通过重试接口重新支付

**场景 3：支付失败（余额不足等）**
- 云函数收到回调但不处理（只处理 SUCCESS）
- 订单状态保持 `pending`
- 用户可以重新支付

**场景 4：云函数回调失败**
- 云函数更新失败不影响后端通知
- 后端会处理完整的业务逻辑
- 确保用户余额正确充值

**场景 5：后端通知失败**
- 云函数已更新订单状态
- 后端通知失败只记录日志
- 可能导致余额未充值
- 补救：定时任务扫描异常订单

#### 两个回调接口的作用

**1. `/api/payment/callback` - 微信官方回调（备用路径）**
- 触发：微信支付服务器直接调用后端
- 功能：验证签名、解密数据、更新订单、充值余额
- 使用场景：云函数故障时的降级方案

**2. `/api/payment/internal/notify` - 内部通知接口（主要路径）**
- 触发：云函数处理完微信回调后通知后端
- 功能：更新订单、充值余额、幂等性检查
- 使用场景：正常的支付成功处理流程

**为什么需要两个回调？**
- 提供容错和灵活性
- 云函数快速响应微信，避免超时
- 后端专注业务逻辑处理
- 职责分离，易于维护

**会不会重复充值？**
- 不会，有多重保护：
  1. 后端幂等性检查（只处理 pending → paid）
  2. 云函数幂等性检查（已 paid 的订单不处理）
  3. balanceService 内部检查（usage_logs 防重复）

```
    ├─ 从数据库加载未完成任务 ✅

    ├─ 超时任务标记为 timeout
    └─ 未超时任务重新执行 ✅
T5: 任务完成或超时恢复次数 ✅
```

**✅ 修复效果：**
- 任务状态持久化到数据库
- 服务重启后自动恢复任务
- 超时任务自动恢复次数
- 用户体验良好

**恢复逻辑（taskQueueService.js）：**
```javascript
async function recoverPendingTasks(executeTaskFn) {
  // 1. 从数据库加载所有 pending/processing 任务
  const tasks = await loadTasksFromDatabase(['pending', 'processing']);
  
  // 2. 检查任务是否超时（1小时）
  for (const task of tasks) {
    const taskAge = Date.now() - new Date(task.createdAt).getTime();
    const maxAge = 60 * 60 * 1000; // 1小时
    
    if (taskAge > maxAge) {
      // 超时任务标记为 timeout，恢复次数
      task.status = 'timeout';
      await persistTask(task);
      await balanceService.restoreBalance(task.userId, task.id, task.mode);
    } else {
      // 未超时任务重新执行
      executeTaskFn(task.id);
    }
  }
}
```

```javascript
// ✅ 新代码：超时任务自动恢复余额
if (taskAge > maxAge) {
  task.status = 'timeout';
  await persistTask(task);
  
  // 恢复用户余额
  try {
    await balanceService.restoreBalance(task.meta.userId, task.id, task.meta.mode);
    logQueue(task.id, '恢复', '✅ 超时任务余额已恢复');
  } catch (restoreError) {
    logQueue(task.id, '恢复', `⚠️ 恢复余额失败: ${restoreError.message}`);
  }
  continue;
}
```

```javascript
  try {
    // 查询逻辑...
  } catch (error) {
    // 网络错误时重试
    if (retryCount < 2 && (error.message.includes('ECONNREFUSED') || error.message.includes('ETIMEDOUT'))) {
      console.warn(`[BalanceService] 检查余额失败，重试 ${retryCount + 1}/2`);
      await new Promise(resolve => setTimeout(resolve, 1000 * (retryCount + 1)));
      return checkBalance(userId, mode, retryCount + 1);
    }
    throw new Error(`检查用户余额失败: ${error.message}`);
  }
}
```
