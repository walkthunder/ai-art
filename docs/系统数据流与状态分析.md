### ✅ 已修复的问题

#### ~~问题1：payment_orders表的外键约束不合理~~ ✅ 已修复

**原问题：**
```sql
-- 旧设计
generation_id VARCHAR(36) NOT NULL  -- ❌ 充值订单无法创建
CONSTRAINT payment_orders_ibfk_2 
FOREIGN KEY (generation_id) REFERENCES generation_history(id) 
ON DELETE CASCADE
```

**修复方案（016_fix_payment_orders_generation_id.sql）：**
```sql
-- 1. 修改 generation_id 为 NULLABLE
ALTER TABLE payment_orders 
MODIFY COLUMN generation_id VARCHAR(36) NULL 
COMMENT '生成记录ID（充值订单可为空）';

-- 2. 删除旧外键约束
ALTER TABLE payment_orders 
DROP FOREIGN KEY IF EXISTS payment_orders_ibfk_2;

-- 3. 重新添加外键约束（允许NULL）
ALTER TABLE payment_orders 
ADD CONSTRAINT payment_orders_ibfk_2 
FOREIGN KEY (generation_id) REFERENCES generation_history(id) 
ON DELETE SET NULL;

-- 4. 新增订单类型字段
ALTER TABLE payment_orders 
ADD COLUMN order_type ENUM('generation', 'recharge') NOT NULL DEFAULT 'generation' 
COMMENT '订单类型: generation-生成订单, recharge-充值订单';

-- 5. 添加索引
ALTER TABLE payment_orders 
ADD INDEX idx_order_type (order_type);
```

**修复效果：**
- ✅ 充值订单可以创建（generation_id = NULL）
- ✅ 生成订单仍然关联 generation_history
- ✅ 订单类型明确区分
- ✅ 外键约束保持完整性

#### ~~问题2：任务状态未持久化~~ ✅ 已修复

**原问题：**
- 任务状态只存储在内存和文件中
- 服务重启后任务状态丢失
- 无法跨实例共享任务状态
- 扣减的次数无法恢复

**修复方案（017_create_tasks_table.sql）：**
```sql
CREATE TABLE IF NOT EXISTS tasks (
  id VARCHAR(36) PRIMARY KEY COMMENT '任务ID（UUID）',
  user_id VARCHAR(36) NOT NULL COMMENT '用户ID',
  mode VARCHAR(20) NOT NULL COMMENT '模式: puzzle-时空拼图, transform-富贵变身',
  status ENUM('pending', 'processing', 'completed', 'failed', 'timeout', 'cancelled') 
    NOT NULL DEFAULT 'pending' COMMENT '任务状态',
  progress INT NOT NULL DEFAULT 0 COMMENT '进度百分比 0-100',
  message TEXT COMMENT '状态消息',
  
  -- 任务参数和结果（JSON格式）
  params JSON NOT NULL COMMENT '任务参数',
  result JSON DEFAULT NULL COMMENT '任务结果',
  error TEXT DEFAULT NULL COMMENT '错误信息',
  
  -- 重试相关
  retry_count INT NOT NULL DEFAULT 0 COMMENT '重试次数',
  max_retries INT NOT NULL DEFAULT 2 COMMENT '最大重试次数',
  
  -- 时间戳
  created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  started_at TIMESTAMP NULL DEFAULT NULL,
  completed_at TIMESTAMP NULL DEFAULT NULL,
  
  -- 索引
  INDEX idx_user_id (user_id),
  INDEX idx_mode (mode),
  INDEX idx_status (status),
  INDEX idx_created_at (created_at),
  INDEX idx_user_status (user_id, status),
  
  -- 外键
  CONSTRAINT tasks_ibfk_1 FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;
```

**代码更新（taskQueueService.js）：**

```javascript
  // 1. 从内存获取

  if (task) return task;
  
  // 2. 从数据库加载

  if (task) return task;

  return task;

// 3. 删除策略：同时删除数据库和文件
async function deleteTask(taskId) {
  taskQueue.delete(taskId);
  await deleteFromDatabase(taskId);
  await deleteFromFile(taskId);
}
```

## 🔍 并发场景分析

### 场景1：用户剩余1次，同时发起2个请求

```
时间线：
T1: 请求A - checkBalance() → 1次 ✅
T2: 请求B - checkBalance() → 1次 ✅
T3: 请求A - createTask() → task-A
T4: 请求B - createTask() → task-B
T5: 请求A - decrementBalance() 
    ├─ SELECT ... FOR UPDATE (获取锁)
    ├─ amount = 1 ✅
    ├─ UPDATE amount = 0
    └─ COMMIT (释放锁)
T6: 请求B - decrementBalance()
    ├─ SELECT ... FOR UPDATE (等待锁...)
    ├─ 获取锁后 amount = 0 ❌
    └─ throw Error('INSUFFICIENT_BALANCE')
```

**结果：**
- 请求A：成功，扣减到0
- 请求B：失败，余额不足

**✅ 结论：并发安全，有行锁保护**

### 场景2：任务失败，重复调用恢复接口

```
时间线：
T1: 任务失败 → restoreBalance(userId, taskId)
    ├─ 检查是否已恢复 → 0条 ✅
    ├─ 检查是否有扣减 → 1条 ✅
    ├─ UPDATE amount = amount + 1
    └─ INSERT restore log
    
T2: 攻击者调用 → restoreBalance(userId, taskId)
    ├─ 检查是否已恢复 → 1条 ❌
    └─ return { success: false, error: 'ALREADY_RESTORED' }
```

**结果：**
- 第一次：成功恢复
- 第二次：拒绝恢复

**✅ 结论：防重复恢复有效**

### 场景3：服务重启导致任务状态丢失（已修复）✅

```
时间线：
T1: 用户发起生成 → 扣减次数 ✅
T2: 任务开始执行 → status: PROCESSING
    ├─ 写入数据库：INSERT INTO tasks (...) ✅
    └─ 写入文件：task-abc-123.json ✅
T3: 服务重启 💥
T4: 服务启动 → 恢复任务
    ├─ 从数据库加载未完成任务 ✅
    ├─ 检查任务是否超时（1小时）
    ├─ 超时任务标记为 timeout
    └─ 未超时任务重新执行 ✅
T5: 任务完成或超时恢复次数 ✅
```

**✅ 修复效果：**
- 任务状态持久化到数据库
- 服务重启后自动恢复任务
- 超时任务自动恢复次数
- 用户体验良好

**恢复逻辑（taskQueueService.js）：**
```javascript
async function recoverPendingTasks(executeTaskFn) {
  // 1. 从数据库加载所有 pending/processing 任务
  const tasks = await loadTasksFromDatabase(['pending', 'processing']);
  
  // 2. 检查任务是否超时（1小时）
  for (const task of tasks) {
    const taskAge = Date.now() - new Date(task.createdAt).getTime();
    const maxAge = 60 * 60 * 1000; // 1小时
    
    if (taskAge > maxAge) {
      // 超时任务标记为 timeout，恢复次数
      task.status = 'timeout';
      await persistTask(task);
      await balanceService.restoreBalance(task.userId, task.id, task.mode);
    } else {
      // 未超时任务重新执行
      executeTaskFn(task.id);
    }
  }
}
```

```javascript
async function checkBalance(userId, mode = null) {

    // 查询逻辑...
  } catch (error) {
    throw new Error(`检查用户余额失败: ${error.message}`);
  }
}

// ✅ 新代码：添加重试机制
async function checkBalance(userId, mode = null, retryCount = 0) {
  try {
    // 查询逻辑...
  } catch (error) {
    // 网络错误时重试
    if (retryCount < 2 && (error.message.includes('ECONNREFUSED') || error.message.includes('ETIMEDOUT'))) {
      console.warn(`[BalanceService] 检查余额失败，重试 ${retryCount + 1}/2`);
      await new Promise(resolve => setTimeout(resolve, 1000 * (retryCount + 1)));
      return checkBalance(userId, mode, retryCount + 1);
    }
    throw new Error(`检查用户余额失败: ${error.message}`);
  }
}
```
